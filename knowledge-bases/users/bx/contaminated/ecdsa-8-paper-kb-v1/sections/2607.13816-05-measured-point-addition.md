# Paper 2607.13816 — Measured in-place arithmetic and point addition

## The workspace conflict

The forward EEA inversion uses one field register as input/output, one clean field register as large workspace, and `O(log n)` small state:

```text
|x>|0>|0_S> -> |x^-1>|0>|Gamma(x)>
```

After multiplying `y` by `x^-1` into accumulator `A`, that accumulator is no longer clean. The inverse EEA still needs a clean `n`-qubit workspace to recover `x` and erase `Gamma(x)`.

The old `Y=y` is mathematically redundant, but it cannot simply be reset because it is part of a coherent computation.

## Hadamard-basis demolition and phase repair

Apply `H^n`, measure `Y`, and obtain classical outcome `b`. The measured field register can be reset and reused. The remaining state acquires only:

```text
(-1)^(b dot y)
```

where the dot product is over bit strings modulo 2.

After inverse EEA has used the reset `Y` as workspace, recompute the old `y` from the surviving values. Apply `Z` on each recomputed bit for which `b_i=1`; this contributes the same phase again and cancels it. Uncompute the temporary `y`.

See [`luo-hadamard-register-recycling.md`](../nodes/luo-hadamard-register-recycling.md).

## In-place division

Interface:

```text
IDiv:
|x>_X |y>_Y |0>_A
  -> |x>_X |y/x>_Y |0>_A
```

Logical sequence:

```text
forward EEA: x -> x^-1, retain Gamma(x)
compute y/x into A
H-measure-reset old Y
inverse EEA using Y as workspace
recompute y = x*(y/x) into Y
apply Z^b
uncompute y
swap Y and A
```

See [`luo-in-place-division.md`](../nodes/luo-in-place-division.md).

## In-place multiplication

The analogous interface is:

```text
IMul:
|x>_X |y>_Y |0>_A
  -> |x>_X |x*y>_Y |0>_A
```

It computes the product in `A`, demolishes old `Y`, recomputes `y` from `x` and `xy` using division/inverse multiplication, repairs the phase, uncomputes, and swaps.

See [`luo-in-place-multiplication.md`](../nodes/luo-in-place-multiplication.md).

## Point-addition schedule

The Figure-14 circuit uses `X`, `Y`, and `A`, one external control, and the small EEA ancillas. In broad terms it:

1. turns coordinate differences into the numerator and denominator;
2. invokes `IDiv` for the slope;
3. squares the slope and updates the new `x`;
4. invokes `IMul` for the new `y`;
5. applies controlled negations and constant-coordinate corrections.

The selected addend is classically precomputed in the resource implementation. Runtime-classical offsets require a different top-level arithmetic wrapper.

## Benchmark inverse caveat

**[INFERENCE]** Mid-circuit demolition is not a unitary gate list that can be reversed mechanically. A benchmark requiring `forward; reverse = identity` needs:

- an explicit inverse protocol;
- compatible storage or replay of measurement outcomes;
- exactly matched classical phase corrections;
- confirmation that reset and conditional operations are legal and scored as expected.

This is the first compatibility test to run before attempting a large hybrid port.
